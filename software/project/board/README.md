# Board support

## Gambos PCB (`gambos-pcb`)

Board support uses a **3-layer CubeMX workflow**:

| Layer | Path | Role |
|-------|------|------|
| Upstream | `board/gambos-pcb_upstream/` | Pristine CubeMX export — do not edit |
| Patches | `board/gambos-pcb_patches/` | Project customizations (tracked in git) |
| Build tree | `board/gambos-pcb/` | Materialized output used by CMake — regenerated by sync |

Application code stays in `app/gambos-pcb/`. Hardware drivers stay in `custom_drivers/`.

### CubeMX regeneration

```bash
# 1. Replace board/gambos-pcb_upstream/ with fresh Cube export
# 2. Materialize patched board tree
./software/project/scripts/sync-cubemx-gambos-pcb.sh
# 3. Build
./software/project/scripts/build.sh
```

`build.sh` runs the sync step automatically.

If a patch fails to apply after Cube changes, fix the patch file(s) under `gambos-pcb_patches/` (see `gambos-pcb_patches/README.md`).

### Build integration

Top-level `CMakeLists.txt` uses `add_subdirectory(board/gambos-pcb/cmake/stm32cubemx)` so Cube's `../../` paths resolve correctly. Toolchain: `cmake/toolchain-gambos-pcb.cmake`.

Firmware app code: `app/gambos-pcb/` — see `app/README.md`.
